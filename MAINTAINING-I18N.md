# Maintaining the Chinese (zh-Hans) translation

The translation project is complete. This document is what replaces it: the
rules for keeping the corpus correct from here on.

Status verified 2026-08-20.

| | Count |
| --- | --- |
| English pages under `content/` (excluding the API) | 272 |
| Translated into zh-Hans | 272 |
| Pages left untranslated on purpose (`content/api/`) | 34 |
| Pages in the Chinese sitemap | 276 |

---

## 1. The rule that matters most

**A translation is a full copy of the English file, not a patch.** Nothing links
the two at build time. If you edit an English page and do not edit its Chinese
copy, the Chinese page keeps serving the old text and the build stays green.

`scripts/check-i18n-drift.js` exists to stop exactly that. It records the SHA-256
of every English source at translation time in `i18n/zh-Hans/SOURCES.json` and
fails when one of them changes.

It is the first step of `npm run check`, so it blocks a release rather than
warning into a log.

```bash
npm run check:i18n-drift      # report drift, exit 1 if any
npm run update:i18n-sources   # re-stamp AFTER updating the Chinese pages
```

### When you change an English page

1. Make the English edit.
2. Make the matching Chinese edit in
   `i18n/zh-Hans/docusaurus-plugin-content-docs/current/<same path>`.
3. Run `npm run update:i18n-sources` to re-stamp the hashes.
4. Run `npm run check`.

Never run step 3 without step 2. Re-stamping without translating is the one way
to defeat the check, and it leaves no trace.

## 2. Interface strings in `src/`

The pages under `content/` are only half the corpus. The other half is the
interface: `src/`, `docusaurus.config.ts`, and the sidebars.

These have their own failure mode, because `<Translate>` resolves by `id`, not
by message:

```js
codeTranslations[id ?? message] ?? message ?? id
```

Change the English text behind an existing id and the old Chinese keeps
shipping, silently. This happened twice while this site was reworked.

`scripts/check-code-drift.js` closes that gap. It extracts the English strings
with Docusaurus itself, records a hash of each one in
`i18n/zh-Hans/CODE_SOURCES.json`, and fails when any of them changes. It also
reports ids that have no Chinese entry, and Chinese entries with no English
source.

```bash
npm run check:code-drift       # report drift, exit 1 if any
npm run update:i18n-sources    # re-stamp BOTH manifests, after translating
```

It covers `code.json`, `navbar.json`, `footer.json`, and `current.json`.

**The one thing it cannot see** is ids built at run time. The demo gallery in
`src/pages/docs/sandbox.html.tsx` composes `demos.item.<Slug>` and
`demos.section.<Name>` from its own data, so static extraction never sees them.
They are exempt from the check and maintained by hand. Their Chinese comes from
the `sidebar_label` of each translated demo page, which keeps the gallery and
the pages it links to using the same words.

`i18n/en/` is generated by this script and is git-ignored. It is deleted and
rebuilt on every run, because `write-translations` keeps any message already on
disk — a stale copy would freeze the baseline and hide the very drift the script
looks for.

## 3. Why the API reference stays English

`content/api/` is generated. `create-api-docs.js` runs `rm -r ./content/api` and
rebuilds all 34 files from the JSDoc comments in `konva.js`. It is not part of
`npm run build`; a maintainer runs it by hand at release time.

A Chinese copy under `i18n/` would survive that wipe, so the English would
regenerate and the Chinese would not. Silent drift is worse than an obvious gap.

Those pages still serve under `/zh-Hans/` as English fallbacks, but
`ignorePatterns: ['/zh-Hans/api/**']` in the sitemap config keeps them out of
Chinese search results, so the site never advertises English pages as Chinese.

If Chinese API docs are wanted, the fix belongs upstream: translate the JSDoc in
the `konva` repository and teach the generator to emit a second locale.

## 4. Rules for editing a translated page

**Never:**

- change a `slug:` value — routes must match across locales
- change `sidebar_position` — it drives the Chinese sidebar order independently
- rename or move a file, including numeric prefixes such as `01_`
- translate code, import paths, JSX, attribute names, or JSON keys
- translate Konva API names — `Stage`, `Layer`, `Transformer`, `draggable`,
  `Konva.Rect` stay in Latin script
- translate code-fence metadata — ` ```js live react ` must be byte-identical or
  the live example dies
- translate Tabs `value=` or `label=` attributes
- change a URL, including its UTM parameters
- add, remove, or reorder headings — anchors depend on them

**Always:**

- translate prose, headings, `title`, `sidebar_label`, `description`, and image
  `alt` text
- keep every other front-matter key byte-identical
- use the terminology below

## 6. Previewing

The dev server serves **one locale at a time**. Plain `npm start` serves English,
and `/zh-Hans/` will 404 there. That is expected, not a bug.

```bash
npm start -- --locale zh-Hans      # http://localhost:3000/zh-Hans/
```

Preview the Chinese locale before releasing a change to it. Several classes of
fault only appear there, because a non-default locale moves `baseUrl` to
`/zh-Hans/`.

---

## 7. Traps

**Assets must go through `useBaseUrl`.** A hardcoded `/assets/…` or `/img/…`
ignores `baseUrl` and 404s under any non-default locale. In production it can
appear to work, because `baseUrl` is `/` and Docusaurus copies `static/` into
each locale directory — so the broken URL still finds the English copy. Use
`useBaseUrlUtils()` and `withBaseUrl(...)` for lists.

**Internal links must use `<Link>`, never a raw `<a href>`.** A raw anchor drops
the active locale and sends a Chinese reader to the English page.

Markdown images are safe: Docusaurus bundles `![](/assets/x.png)` and applies
`baseUrl` for you.

**Code fences are balanced, and must stay that way.** 40 files once ended with
an unbalanced fence — 32 with a stray trailing ` ``` `, 8 missing a closing one.
They rendered only because nothing followed the fence. All are fixed in both
locales. If you add a fence, close it, and make the same change on both sides.

**Four-backtick fences are valid.** Some files close a ` ``` ` block with
` ```` `. Do not normalise them.

---

## 8. Verification

```bash
npm run check
```

Runs, in order: the page drift check, the interface-string drift check, the
TypeScript check, both locale builds (`onBrokenLinks` and `onBrokenAnchors` are
`throw`), and both sitemap checks.
