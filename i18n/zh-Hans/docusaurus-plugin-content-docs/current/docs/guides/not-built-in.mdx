Konva 负责绘制图形、对它们做变换，并告诉你点击了什么。人们期待图像或矢量编辑器具备的若干功能
并不在其中，而且你也找不到对应的方法。本页把它们一一列出，好让你不必继续寻找，直接着手替代方案。

[为什么选择 Konva？](/zh-Hans/docs/guides/why-konva.html) 从整体类别的层面回答同样的问题——
游戏引擎、3D、图表。本页讨论的是具体功能。

## 透视变形与网格形变

**不支持，而且这不是"缺少某个方法"的问题。** Canvas 2D 的变换是仿射变换：`setTransform()`
接受六个数字，可以平移、缩放、旋转和斜切，但无法让平行线汇聚。透视需要射影变换，而该 API
根本无法表达它。Konva 无论加什么都改变不了这一点。

有三条可行路径：

- **三角剖分。** 把图像切成三角网格，每个三角形用各自的仿射变换加裁剪区域来绘制。三角形足够多时，
  结果看起来就像变形。宣称支持"变形"的 2D 库内部就是这么做的。这需要相当多的代码，接缝处也需要仔细处理。
- **只为那一个元素使用 WebGL。** 在 WebGL canvas 中渲染变形后的图像，再把结果交给 `Konva.Image`。
  `glfx.js` 是较轻量的选择，Three.js 场景则更重。
- **对平面使用 CSS 3D。** 如果你只是要变形一个矩形对象，而且它不需要出现在导出的 Canvas 中，
  那么在舞台上方放置一个带 `transform: perspective(...) rotate3d(...)` 的 DOM 元素要省事得多。
  它不会出现在 `toDataURL()` 的结果里。

## 路径布尔运算

**不支持。** `Konva.Path` 和 `Konva.Line` 上都没有 `union()`、`subtract()` 或
`intersect()`。Konva 存储路径数据并绘制它，但不对它做几何运算。

请用多边形裁剪库计算结果，然后把输出作为普通图形交给 Konva：

```js
// polybooljs、martinez-polygon-clipping 等库都返回普通的环形点集
const result = PolyBool.union(
  { regions: [shapeARing], inverted: false },
  { regions: [shapeBRing], inverted: false }
);

layer.add(new Konva.Line({
  points: result.regions[0].flat(),
  closed: true,
  fill: 'black',
}));
```

如果布尔运算是你产品的核心而不是偶尔用到，[Paper.js](http://paperjs.org/) 内置了它们，
是更合适的选择。

对于常见的*视觉*效果，你可能根本不需要真正的几何运算：`globalCompositeOperation` 可以从一个
图形中挖去另一个，[裁剪](/zh-Hans/docs/clipping/Clipping_Regions.html)可以把绘制限制在某个
区域内。两者都不会改变底层路径，因此命中检测仍然使用原始图形。

## 套索选择

**没有对应的 API**，但这一项你可以自己实现，而且它主要是数学问题而不是 Konva 问题。

在指针移动时把自由手绘路径画成一条 `Konva.Line`，闭合之后再逐个测试候选对象是否落在多边形内：

```js
function pointInPolygon(point, polygon) {
  let inside = false;
  for (let i = 0, j = polygon.length - 2; i < polygon.length; j = i, i += 2) {
    const xi = polygon[i], yi = polygon[i + 1];
    const xj = polygon[j], yj = polygon[j + 1];
    const hits = yi > point.y !== yj > point.y &&
      point.x < ((xj - xi) * (point.y - yi)) / (yj - yi) + xi;
    if (hits) inside = !inside;
  }
  return inside;
}

const selected = layer.children.filter((node) => {
  const box = node.getClientRect();
  return pointInPolygon({ x: box.x + box.width / 2, y: box.y + box.height / 2 }, lassoPoints);
});
```

测试中心点是廉价版本。测试每个角点、或图形自身的轮廓开销更大，但在大图形上表现更好——
请根据用户实际选择的内容来取舍。

请注意 `Konva.Util.haveIntersection` 只做**轴对齐包围盒**相交判断。它适合橡皮筋矩形选择，
不适合套索。矩形选择的做法参见
[矩形选择](/zh-Hans/docs/select_and_transform/Basic_demo.html)。

## 油漆桶填充

**不支持**，而且在动手实现之前值得先想清楚，因为它是在矢量场景图中执行的栅格操作。

Konva 的图形是带属性的对象。而油漆桶作用于像素：读取区域，从种子点向外扩散直到颜色不再匹配，
再把结果写回去。输出是位图而不是图形——因此它无法像场景中其他内容那样被选中、拖动、
重新设置样式或序列化。

如果你仍然需要它，请在专门的栅格图层上操作：

```js
const canvas = document.createElement('canvas');
const ctx = canvas.getContext('2d');
// ……对 ctx.getImageData(...) 执行扫描线填充，再写回去……

const painted = new Konva.Image({ image: canvas });
layer.add(painted);
layer.draw();   // canvas 在 Konva 之外发生了变化，因此需要主动请求重绘
```

请把该图像放在它自己的图层上，位于矢量内容的上方或下方。把绘制的像素和可编辑图形混在同一个
图层里，正是麻烦的开始——图层每次重绘都会重画你的填充。

## 为什么这些功能不会加入

每一项都会把某个庞大的东西拉进核心：几何引擎、WebGL 管线，或者栅格编辑器。Konva 是负责绘制
图形并分发事件的那一层，而上面提到的库在各自的领域做得比内置实现更好。如果某个功能确实只是在
Konva 已有能力之上再写几十行代码——套索选择就是例子——那就把做法写出来，而不是把它塞进库里。
