Konva draws shapes, transforms them, and tells you what you clicked. Several
things people expect from an image or vector editor are not part of that, and
there is no method to find. This page names them, so you can stop looking and
get on with the workaround.

[Why Konva?](/docs/guides/why-konva.html) covers the same question at the level
of whole categories — game engine, 3D, charting. This page is about specific
features.

## Perspective warp and mesh deformation

**Not available, and not a matter of a missing method.** Canvas 2D transforms
are affine: `setTransform()` takes six numbers, which can translate, scale,
rotate and skew, but cannot converge parallel lines. Perspective needs a
projective transform, which the API has no way to express. Nothing Konva could
add would change that.

Three routes work:

- **Triangulate.** Split the image into a mesh of triangles and draw each one
  with its own affine transform and a clipped region. Enough triangles and the
  result looks like a warp. This is what 2D libraries that advertise "warping"
  do internally. It is a real amount of code and the seams need care.
- **Use WebGL for that one element.** Render the warped image in a WebGL canvas
  and feed the result into a `Konva.Image`. `glfx.js` is a small option; a
  Three.js scene is the heavier one.
- **CSS 3D for a flat plane.** If you are warping one rectangular thing and it
  does not need to be part of the exported canvas, a DOM element with
  `transform: perspective(...) rotate3d(...)` positioned over the stage is far
  less work. It will not appear in `toDataURL()`.

## Boolean path operations

**Not available.** There is no `union()`, `subtract()` or `intersect()` on
`Konva.Path` or `Konva.Line`. Konva stores path data and draws it; it does not
do geometry on it.

Compute the result with a polygon-clipping library, then hand the output to
Konva as an ordinary shape:

```js
// polybooljs, martinez-polygon-clipping and similar all return plain rings
const result = PolyBool.union(
  { regions: [shapeARing], inverted: false },
  { regions: [shapeBRing], inverted: false }
);

layer.add(new Konva.Line({
  points: result.regions[0].flat(),
  closed: true,
  fill: 'black',
}));
```

If boolean operations are central to your product rather than occasional,
[Paper.js](http://paperjs.org/) has them built in and is the better fit.

For the common *visual* cases you may not need real geometry at all:
`globalCompositeOperation` can punch one shape out of another, and
[clipping](/docs/clipping/Clipping_Regions.html) restricts drawing to a region.
Neither changes the underlying path, so hit detection still uses the original
shape.

## Lasso selection

**Not available as an API**, but this one you can build, and it is mostly a
maths problem rather than a Konva problem.

Draw the freehand path as a `Konva.Line` while the pointer moves, then when it
closes, test each candidate against the polygon:

```js
function pointInPolygon(point, polygon) {
  let inside = false;
  for (let i = 0, j = polygon.length - 2; i < polygon.length; j = i, i += 2) {
    const xi = polygon[i], yi = polygon[i + 1];
    const xj = polygon[j], yj = polygon[j + 1];
    const hits = yi > point.y !== yj > point.y &&
      point.x < ((xj - xi) * (point.y - yi)) / (yj - yi) + xi;
    if (hits) inside = !inside;
  }
  return inside;
}

const selected = layer.children.filter((node) => {
  const box = node.getClientRect();
  return pointInPolygon({ x: box.x + box.width / 2, y: box.y + box.height / 2 }, lassoPoints);
});
```

Testing the centre point is the cheap version. Testing every corner, or the
shape's own outline, costs more and behaves better on large shapes — pick
according to what your users are selecting.

Note that `Konva.Util.haveIntersection` is **axis-aligned box** intersection
only. It is the right tool for a rubber-band rectangle, and the wrong one for a
lasso. See [rectangle selection](/docs/select_and_transform/Basic_demo.html) for
the box case.

## Flood fill (paint bucket)

**Not available**, and worth thinking about before you build it, because it is a
raster operation inside a vector scene graph.

Konva shapes are objects with attributes. A flood fill works on pixels: read the
region, walk outwards from the seed while the colour matches, write the result
back. The output is a bitmap, not a shape — so it cannot be selected, dragged,
restyled or serialised the way the rest of your scene can.

If you still need it, work on a dedicated raster layer:

```js
const canvas = document.createElement('canvas');
const ctx = canvas.getContext('2d');
// ... run your scanline fill against ctx.getImageData(...) and put it back ...

const painted = new Konva.Image({ image: canvas });
layer.add(painted);
layer.draw();   // the canvas changed outside Konva, so ask for the redraw
```

Keep that image on its own layer, above or below the vector content. Mixing
painted pixels into the same layer as editable shapes is where this gets
painful — every redraw of the layer repaints your fill.

## Why these stay out

Each would pull something large into the core: a geometry engine, a WebGL
pipeline, or a raster editor. Konva is the layer that draws shapes and routes
events, and the libraries above do those jobs better than a built-in version
would. Where a feature is genuinely a few dozen lines on top of what Konva
already exposes — lasso selection is the example here — the approach is written
out rather than shipped.
